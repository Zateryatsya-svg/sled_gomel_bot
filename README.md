# 🕵️‍♂️ Бот «Сокровище Парка Паскевичей»

Telegram-бот детективного квеста по Гомельскому парку. Написан на Python + aiogram 3.

## Структура проекта

```
sled_gomel_bot/
├── bot.py              # логика бота (движок квеста, обработчики)
├── content.json         # ВЕСЬ текст квеста: вопросы, ответы, досье, реплики «Тени»
├── answer_utils.py      # проверка ответов (регистр, опечатки, альтернативы, числа с погрешностью)
├── storage.py            # сохранение прогресса пользователей в SQLite
├── requirements.txt
├── .env.example
└── README.md
```

**Редактировать текст квеста нужно только в `content.json`** — код трогать не придётся.
Формат содержимого файла:

- `steps` — массив точек маршрута по порядку. У каждой точки есть `"type"`:
  - `"single"` — обычная точка с одним вопросом (буквы С, К, Р, О, В и т.д.)
  - `"multi"` — точка с несколькими уликами подряд (Дворец, Румянцев)
  - `"rest"` — точка отдыха без вопроса, только кнопка «Дальше»
  - `"rest_question"` — точка отдыха с лёгким вопросом, но без буквы (Бархат амурский, Фонарь)
  - `"final"` — финальная точка + ввод собранного слова
- `"answers"` — список допустимых текстовых ответов (можно дописывать свои варианты опечаток)
- `"numeric"` — для числовых ответов: `{"target": 4, "tolerance": 1}` значит правильный ответ 4, но 3 и 5 тоже засчитаются
- `"dossier"` — историческая справка, показывается после правильного ответа
- `"shadow_after"` — реплика «Тени», отправляется отдельным сообщением

## Как проверить работу ответов

Бот сверяет ответы без учёта регистра, пробелов и пунктуации, поэтому «Пика», «пика!», «  ПИКА  » — всё это один и тот же правильный ответ. Числовые ответы с `tolerance` принимают отклонение в обе стороны.

## Шаг 1. Регистрация бота у @BotFather и получение токена

1. Откройте Telegram и найдите **@BotFather** (официальный бот для создания ботов).
2. Отправьте команду `/newbot`.
3. Введите отображаемое имя бота (то, что видят люди), например: `Сокровище Паскевичей`.
4. Введите **username** бота. Важно: username в Telegram **обязательно должен заканчиваться на `bot`** — просто `sled_gomel` BotFather не примет. Поэтому используйте один из вариантов:
   - `sled_gomel_bot`
   - `sledgomel_bot`
   - `gomel_sled_bot`
   - `sokrovishe_gomel_bot`

   Попробуйте их по очереди в указанном порядке — BotFather сразу скажет, если имя занято, и предложит попробовать следующее.
5. После успешного создания BotFather пришлёт сообщение вида:
   ```
   Done! Congratulations on your new bot...
   Use this token to access the HTTP API:
   123456789:AAExampleTokenXXXXXXXXXXXXXXXXXXXXX
   ```
   Это и есть ваш токен — скопируйте его.
6. (Необязательно, но красиво) Пришлите BotFather ещё несколько команд для оформления:
   - `/setdescription` — добавить описание бота (то, что видно на пустом экране чата)
   - `/setabouttext` — короткое описание в профиле
   - `/setuserpic` — загрузить аватар (например, картинку с воротами парка или гербом Гомеля)
   - `/setcommands` — задать список команд, отправьте боту такой текст:
     ```
     start - Начать расследование
     progress - Показать текущий прогресс
     reset - Начать заново
     ```

## Шаг 2. Запуск бота локально (чтобы проверить, что всё работает)

1. Установите Python 3.10+ (проверить: `python3 --version`).
2. Распакуйте архив с проектом и перейдите в папку:
   ```bash
   cd sled_gomel_bot
   ```
3. Создайте виртуальное окружение и установите зависимости:
   ```bash
   python3 -m venv venv
   source venv/bin/activate        # на Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```
4. Скопируйте `.env.example` в `.env` и вставьте туда свой токен:
   ```bash
   cp .env.example .env
   ```
   Откройте `.env` в текстовом редакторе и замените строку на:
   ```
   BOT_TOKEN=ваш_настоящий_токен_от_BotFather
   ```
5. Запустите бота:
   ```bash
   python bot.py
   ```
6. В логе должно появиться `Бот запущен, начинаю polling...`. Откройте своего бота в Telegram и отправьте `/start`.

Если всё работает — переходите к деплою, чтобы бот работал 24/7 без вашего компьютера.

## Шаг 3. Бесплатный деплой на Railway (работает круглосуточно)

Railway даёт бесплатный пробный баланс, которого при полностью бесплатном тарифе обычно хватает на такого лёгкого бота на первое время; если баланс закончится, там же можно привязать карту и перейти на минимальный платный план (несколько долларов в месяц). Более новая бесплатная альтернатива — [Render](https://render.com) (Free Web Service + Cron, но там бот "засыпает" без трафика) или [Fly.io](https://fly.io). Ниже — инструкция именно для Railway, как вы просили.

### 3.1. Подготовка репозитория на GitHub

1. Создайте новый репозиторий на [github.com](https://github.com) (например, `sled-gomel-bot`).
2. Загрузите туда содержимое папки `sled_gomel_bot` (все файлы, кроме `.env` — его загружать не нужно, токен передаётся через настройки Railway, а не через код).
3. Убедитесь, что в репозитории есть `.gitignore` со строкой `.env`, чтобы случайно не закоммитить токен (создайте файл `.gitignore` с содержимым `.env` и `__pycache__/`, если его ещё нет).

### 3.2. Создание проекта в Railway

1. Зайдите на [railway.app](https://railway.app) и зарегистрируйтесь (удобнее всего — через GitHub аккаунт).
2. На дашборде нажмите **New Project** → **Deploy from GitHub repo**.
3. Выберите ваш репозиторий `sled-gomel-bot`. Railway разрешит доступ к GitHub, если ещё не разрешён — подтвердите.
4. Railway автоматически определит, что это Python-проект по `requirements.txt`.

### 3.3. Настройка переменных окружения

1. Внутри проекта откройте вкладку **Variables**.
2. Добавьте переменные:
   - Name: `BOT_TOKEN`, Value: ваш токен от BotFather
   - Name: `ADMIN_IDS`, Value: ваш Telegram user_id (узнать у [@userinfobot](https://t.me/userinfobot)) — нужно для команд `/gencode`, `/codestats`, `/revoke`
3. Сохраните.

### 3.4. Настройка команды запуска

1. Откройте вкладку **Settings** созданного сервиса.
2. В разделе **Deploy** найдите поле **Start Command** и укажите:
   ```
   python bot.py
   ```
   (Если поле уже что-то определило автоматически неправильно — впишите вручную именно эту команду.)
3. Важно: этот бот использует **polling** (сам опрашивает Telegram), поэтому никакой домен/webhook/порт настраивать не нужно — просто должен постоянно работать процесс.

### 3.5. Хранение прогресса пользователей (SQLite) на Railway

По умолчанию файловая система Railway **не постоянная** — при каждом новом деплое файл `quest_progress.db` будет создан заново, и весь прогресс игроков обнулится. Чтобы прогресс сохранялся между деплоями:

1. В проекте Railway откройте **+ New** → **Volume**.
2. Смонтируйте том, например, в `/data`.
3. В `storage.py` замените строку
   ```python
   DB_PATH = "quest_progress.db"
   ```
   на
   ```python
   DB_PATH = "/data/quest_progress.db"
   ```
4. Закоммитьте изменение и запушьте — Railway передеплоит бота автоматически, и прогресс уже не будет теряться между обновлениями кода.

(Если для вас это не критично — например, если это одноразовое городское мероприятие и обновлять код после старта не планируется — можно оставить как есть, прогресс всё равно сохраняется между сообщениями в рамках работы одного и того же процесса, теряется только при передеплое.)

### 3.6. Запуск

1. После настройки Railway автоматически соберёт и запустит бота (или нажмите **Deploy** вручную).
2. Проверьте логи (вкладка **Deployments** → открыть последний деплой → **View Logs**) — там должна появиться строка `Бот запущен, начинаю polling...`.
3. Откройте бота в Telegram и отправьте `/start` — если всё настроено верно, он ответит.

Теперь бот работает круглосуточно, даже если ваш компьютер выключен.

## Команды бота

**Для игроков:**
- `/start` — начать (покажет реквизиты оплаты, если доступа ещё нет; или продолжит/предложит начать заново, если уже оплачено)
- `/progress` — посмотреть текущую точку и собранные буквы
- `/reset` — сбросить прогресс прохождения (доступ/оплата не сбрасывается)

**Для организатора (нужен ваш user_id в `ADMIN_IDS`):**
- `/gencode [N] [пометка]` — выдать код(ы) заранее, см. раздел про оплату ниже
- `/codestats` — статистика по кодам
- `/revoke КОД` — отвязать код от пользователя

## Что делать, если хочется что-то поправить в тексте квеста

Просто откройте `content.json`, найдите нужную точку по `"id"` (например, `"gate"`, `"palace"`, `"tower"`) и меняйте текст в кавычках. Файл — обычный JSON, следите только за тем, чтобы не потерять запятые и кавычки. После изменений перезапустите бота (`python bot.py` локально или сделайте `git push`, если он уже на Railway — задеплоится автоматически).

Чтобы добавить альтернативную формулировку ответа — просто допишите строку в список `"answers"`, например:
```json
"answers": ["пика", "пики", "копьё"]
```

## 🔒 Оплата и доступ

Бот больше не пускает всех подряд — доступ открывается только после оплаты. Сейчас (пока не подключён платёжный провайдер) это устроено так: **весь процесс происходит прямо в переписке с ботом**, без отдельного сайта-кассы.

### Как это выглядит для покупателя

1. Человек находит кнопку/ссылку «Играть» на вашем сайте (или сканирует QR на афише) — она ведёт просто на `t.me/sled_gomel_bot`, без всяких кодов.
2. Пишет боту `/start` → бот сразу показывает реквизиты для оплаты (номер карты и/или QR для перевода через банковское приложение) и цену — всё это редактируется в `content.json` → `"payment"` → `"intro"`.
3. Человек переводит деньги и пишет боту любое сообщение («Оплатил(а)», скрин чека — не важно).
4. Бот тут же отвечает «спасибо, проверяю» — и **мгновенно** пересылает вам (организатору) эту заявку с кнопкой «✅ Подтвердить и открыть доступ».
5. Вы видите оплату у себя в банке → нажимаете кнопку → бот сам создаёт код, привязывает его к этому человеку и **тут же в его чате** начинает квест. Больше ничего пересылать и копировать не нужно.

Это решает сразу две вещи: у вас не нужно вручную генерировать код и пересылать QR каждый раз (один тап — и всё), а покупателю не нужно ждать, пока вы увидите сообщение в директе где-то ещё — заявка приходит вам как push-уведомление прямо в Telegram, в реальном времени.

### Настройка

**Шаг 1.** В `.env` впишите свой Telegram user_id в `ADMIN_IDS` (узнать id — написать боту [@userinfobot](https://t.me/userinfobot)). Можно указать несколько через запятую — тогда заявки увидят все.

**Шаг 2.** Отредактируйте реквизиты в `content.json` → `"payment"` → `"intro"`: впишите реальный номер карты, цену и текст.

**Шаг 3 (необязательно, но красивее).** Сгенерируйте в приложении своего банка QR для перевода (обычно раздел «Получить перевод» / «Мои реквизиты») и положите файл как `assets/payment_qr.png` (см. `assets/README_PAYMENT_QR.txt` — там подробная инструкция). Бот сам подхватит картинку и будет присылать её вместе с текстом. Если файла нет — просто пришлёт текстовую инструкцию, тоже нормально работает.

### Альтернативный способ: коды и QR наперёд (для афиш, партий, розыгрышей)

Помимо основного сценария «оплата в чате», остаётся и старый механизм — на случай, если понадобится, например, раздать доступ на офлайн-мероприятии или напечатать QR на афише у входа в парк:

- `/gencode [N] [пометка]` — сгенерировать код(ы) заранее. Если N не указано или равно 1 — сразу пришлёт готовый QR картинкой, можно сразу переслать. Если N от 2 до 10 — по картинке на каждый код. Если N больше 10 — только текстовый список (для печати).
- `/codestats` — сводка: сколько кодов всего, сколько ещё не использовано / в процессе / завершено
- `/revoke КОД` — отвязать код от пользователя и сделать снова свободным (на случай ошибки или возврата денег)

Для партии на печать:
```bash
python generate_codes.py 20 "партия на афишу"
python make_qr.py sled_gomel_bot --file codes_output.txt
```

Оба способа выдачи доступа используют одну и ту же защиту: код/доступ привязывается намертво к первому Telegram-аккаунту, который его открыл — переслать другому не получится.

### Когда оформите приём платежей через bePaid/WebPay (на будущее)

Ручное подтверждение в чате — рабочий вариант для старта, особенно пока неясен объём потока. Но если позже захотите убрать себя из цепочки полностью — то есть чтобы оплата картой/ЕРИП на сайте сама открывала доступ без вашего участия — понадобится:

1. Дождаться одобрения заявки на bePaid/WebPay (карты и/или ЕРИП — вы уже начали оформление).
2. Добавить на сайт (или в бота) обработчик webhook от платёжной системы — уведомление «оплата прошла».
3. По этому уведомлению автоматически дёргать ту же самую функцию `storage.create_code()` + `storage.activate_code()`, которая уже используется в кнопке «Подтвердить» — то есть переиспользовать готовую логику, просто вызывать её из вебхука вместо тапа по кнопке.

Когда одобрят подключение — возвращайтесь, соберём эту часть под конкретный формат уведомлений провайдера.

### Важно про хранение данных при деплое

Коды и прогресс хранятся в той же базе `quest_progress.db` (или `/data/quest_progress.db`, если вы уже настроили Volume на Railway — см. раздел про деплой выше). Если генерируете коды локально через `generate_codes.py`, а бот при этом уже развёрнут на Railway — эти коды нужно генерировать **на той же базе, которую использует продакшн-бот** (то есть либо через команду `/gencode` прямо в самом развёрнутом боте, либо подключаясь к тому же Volume).
